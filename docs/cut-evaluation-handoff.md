# ITDA Studio 컷 연출 평가 구현 인수인계

배치 생성된 컷마다 **Fidelity(객체 무결성), BF(브랜드 적합도), TQ(기술적 품질)**를 평가한다. 종합 모델이 컷별 채택 가능성을 계산해 자동 채택, 사용자 검토, 자동 제외로 분류한다. 개별 모듈은 점수와 평가 가능 상태를 종합 모델에 전달한다.

## 평가 항목

| 항목 | 입력 | 평가 방식 | 점수 |
| --- | --- | --- | --- |
| Fidelity | 원본 제품 이미지 + 생성 컷의 제품 영역 | 같은 DINOv2 모델로 추출한 두 특징을 결합해 회귀 모델에 입력 | `100 × 모델 출력` |
| BF | 생성 컷 + 선택한 브랜드 레퍼런스 Pool | 브랜드 임베딩과 결과 임베딩의 비교 특징을 회귀 모델에 입력 | `100 × 모델 출력` |
| TQ | 원본 제품 이미지 + 생성 컷 | 결과의 채도·음영 대비·흐림을 CV로 측정하고 원본 제품 특성을 참고해 심각도 산출 | `100 × (1 − 심각도)` |

세 식은 모델 출력 또는 심각도가 0~1 범위라는 전제다. 구매전환과 CTR은 고객사의 실제 이용·성과 데이터를 별도로 검증할 과제로 둔다. VMD 미감 평가는 TQ로 대체했다. GPT Decisions API로 점수를 산출한 뒤 후보정하는 방식은 보류했다.

### Fidelity

- 원본과 결과에서 의뢰 제품 영역을 뽑아 같은 모델로 인코딩한다. 원본에 투명 마스크가 있으면 활용한다. 연출 컷에는 소품과 다른 가구가 함께 있을 수 있으므로 대상 제품 식별과 분할을 확인한다. rembg는 제품이 명확한 컷에서 비교할 후보이며, 복잡한 컷은 제품 검출 후 분할을 검토한다.
- 입력은 RGB를 기본으로 하고 중립 배경, 종횡비, 크롭 여백을 일관되게 적용한다. Grayscale은 형태 비교용 보조 특징 후보다. 색상 보존에 필요한 RGB 정보는 유지한다.
- 첫 비교 모델은 `concat(f_ref, f_gen)`을 사용한다. 절댓값 차이, 원소별 곱, 패치·부위 특징은 검증 결과에 따라 추가한다. DINOv2 가중치를 고정하고 작은 예측층부터 학습하며 원본 특징을 재사용한다.
- 시점·각도 변화, 정상 가림, 분할 실패를 실제 부품 변형과 구별해야 한다. 공통으로 보이는 부위를 비교하고, 가려지거나 원본에 없는 면은 평가 가능 상태에 반영한다. 낮은 비교 가능성과 낮은 Fidelity 점수를 별도로 기록한다.
- 사람의 연속 보존 점수가 있으면 그 점수를 회귀 목표로 사용할 수 있다. 현재 UI의 이진 피드백으로 시작한다면 logistic regression으로 무결성 기준에서 허용될 가능성을 예측하는 안을 우선 검증한다. 연속 점수의 정답을 얻으려면 별도 검수 라벨이 필요하다.

### BF

- 사용자는 브랜드 레퍼런스 Pool을 생성·삭제하고 제품 이미지와 연출 이미지를 추가·제거할 수 있다. 제품 이미지는 제품군·소재·디자인의 맥락을, 연출 이미지는 공간·색채·조명·소품 등 시각적 기준을 제공한다.
- 생성 요청에서 Pool을 선택하면 생성과 평가에 같은 Pool 버전을 사용한다. Pool 미지정 시 생성에는 브랜드 조건을 적용하지 않고 평가의 BF 상태를 `미적용`으로 기록한다. 점수 산출에는 선택한 Pool의 브랜드 표현 범위와 결과의 정합성을 반영한다.
- 브랜드 임베딩과 결과 임베딩의 비교 특징을 점수 모델에 전달한다. Pool 임베딩의 구성 방식과 회귀 모델의 초기 학습 기준은 구현 시 정한다. 채널별 파일·배치 규격을 BF에 포함할 범위도 남아 있다.
- BF 사유로 제외된 결과는 해당 Pool의 부정 검수 사례에 추가한다. 채택된 결과는 Pool의 긍정 검수 사례에 추가하며 종합 채택에서 유래한 약한 신호임을 표시한다. 두 검수 사례 목록은 사용자가 직접 지정한 기준 이미지와 분리한다.
- 검수 사례에는 Pool 버전과 프로젝트 조건을 함께 남긴다. 초기에는 사례 하나의 영향력을 제한하고, 사례 활용 방식과 반영 수준은 검증 후 정한다. Pool 수정·삭제 이후의 기존 평가 근거 보존 정책도 필요하다.

### TQ

허용 범위에서는 심각도를 0으로 두고, 극단적인 경우에만 감점한다. CV 측정과 심각도 변환을 분리한다.

| 진단 항목 | CV 측정 후보 | 해석 기준 |
| --- | --- | --- |
| 과도한 채도 | HSV 채도 분포와 고채도 픽셀 비율 | 원래 선명한 제품과 의도적인 강조색을 고려한다. |
| 과도한 밝기·음영 대비 | 휘도 분포, 극단 휘도 비율, 국소 대비 | 흰 벽·검은 제품과 노출로 인한 제품 디테일 손실을 구분한다. |
| 과도한 흐림 | Laplacian 분산, 경사도 등 고주파 성분 | 주제품의 선명도를 우선 측정하고, 의도적인 배경 흐림과 입력 해상도를 고려한다. |

초기에는 고정된 허용 범위와 감점 곡선을 사용한다. 세 심각도를 결합하는 초기 후보는 최댓값이다. 실제 컷으로 임계값과 결합 방식을 검증한다. 이후 학습 모델로 TQ 제외 가능성을 추정한다면, 이를 물리적 결함량과 구분해서 해석한다.

## 종합 판단과 피드백

- 종합 logistic regression에는 Fidelity·BF·TQ 점수와 각 항목의 적용·평가 가능 상태를 입력하는 구성을 우선 검증한다. 출력에 100을 곱한 값은 사용자 채택 가능성을 나타낸다. 낮은 임계값 아래는 자동 제외, 높은 임계값 이상은 자동 채택, 그 사이는 사용자 검토로 보낸다. 초기 모델과 임계값은 검수 데이터로 정한다.
- BF 미적용과 분할·비교 실패를 결측 사유별로 보존한다. BF에 임의의 0점을 넣으면 풀 미지정이 브랜드 불일치로 해석된다. 적용 여부를 입력으로 명시하거나 BF 적용 여부에 따라 종합 모델을 나누는 방식을 비교한다.
- 사용자는 컷마다 적합 또는 부적합을 선택한다. 부적합 사유는 Fidelity·BF·TQ 중 하나 이상을 선택하며 하위 항목 입력은 받지 않는다.

| 사용자 판단 | 종합 모델 | Fidelity | BF | TQ |
| --- | --- | --- | --- | --- |
| 적합 | 명시적 긍정 | 비교 특징을 약한 긍정 후보로 저장 | 지정 Pool의 긍정 검수 사례에 추가 | CV 측정 벡터를 약한 긍정 후보로 저장 |
| 부적합 | 명시적 부정 한 건 | Fidelity 선택 시 비교 특징을 부정 사례로 저장 | BF 선택 시 지정 Pool의 부정 검수 사례에 추가 | TQ 선택 시 전체 CV 측정 벡터를 부정 사례로 저장 |

선택되지 않은 제외 사유는 미라벨로 유지한다. 종합 채택으로 얻은 약한 긍정은 개별 항목을 직접 확인한 정답과 구분하고, 실제 학습 사용 여부와 가중치를 검증한다. TQ의 하위 원인은 사용자 피드백에 없으므로, TQ 부정 한 건에서 채도·휘도·흐림 중 특정 원인을 확정할 수 없다. 누적 측정 벡터로 허용 범위·감점 함수 또는 TQ 제외 예측 모델을 조정한다.

## 실행과 검증

- Next.js가 Pool 관리, 평가 작업 등록, 결과 표시, 사용자 검수를 담당한다. Python 작업자는 제품 분할, DINOv2 특징 추출, OpenCV 측정, 점수 추론·학습을 담당하는 구성을 권장한다. 배치 평가는 비동기로 처리하고 컷별 결과를 저장한다.
- 결과에는 원본·결과 식별자, 프로젝트와 생성 조건, Pool 버전, 전처리·모델 버전, 비교 특징·CV 측정값, 항목별 점수·평가 상태, 종합 점수와 사용자 판단·사유를 연결한다.
- 피드백은 해당 컷에 즉시 반영하고 학습용으로 저장한다. 누적 데이터를 기존 사례와 함께 학습한 뒤 검증을 통과한 버전을 적용한다. 회색지대 사례에 편중되지 않도록 자동 채택·제외 결과도 일부 표본 검수한다.
- Fidelity는 제품 단위로 학습셋과 검증셋을 나누고, 정상적인 시점·가림 변화와 실제 부품 변형을 모두 포함한다. BF는 같은 컷에 서로 다른 Pool을 적용했을 때 점수가 적절히 달라지는지 확인한다. TQ는 의도적인 밝기·채도·배경 흐림을 결함과 구분하는지 확인한다.
- 관제 성능은 자동 채택 컷의 불량 비율, 정상 컷의 자동 제외 비율, 사용자 검토 비율로 확인한다. DINOv2 S/B의 실제 메모리·처리 시간은 초기 16GB VRAM 환경에서 해상도·배치 크기·생성 모델 동시 구동 조건별로 측정한다.
